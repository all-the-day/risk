# 技术方案落地

## 1. 结论先行

这个项目建议采用：

- **前后端一体化开发**
- **逻辑分层，不做物理拆分**
- **单仓库、单项目、单部署**

推荐技术栈：

- 前端框架：**Next.js**
- 语言：**TypeScript**
- 数据库：**PostgreSQL**
- ORM：**Prisma**
- UI：**Tailwind CSS**
- 部署：**Docker + 云服务器**

## 2. 为什么不建议一开始前后端分离

你的产品当前阶段是一个非常典型的 MVP，核心任务是验证：

1. 用户会不会每天来用
2. 团体完成机制有没有吸引力
3. 匿名协作的产品气质是否成立

在这个阶段，如果前后端拆分，会额外带来这些成本：

- 接口定义和联调成本
- 鉴权和会话传递成本
- 跨域和部署复杂度
- 两套工程规范和目录结构
- 小功能迭代变慢

对你现在的产品来说，这些成本都不值。

## 3. 为什么选择 Next.js

Next.js 适合这类产品，因为它天然适合做完整的 Web 应用：

- 页面路由、接口、服务端逻辑都能放在一个项目里
- 适合做登录、打卡、状态展示这种轻交互产品
- 后续如果要扩展，也可以平滑拆分

你现在这个阶段最重要的是：

- 快速上线
- 快速改页面
- 快速改数据结构

Next.js 在这个目标上最稳。

## 4. 建议的项目结构

建议使用单仓库结构：

```text
app/
  (auth)/
  (main)/
  api/
components/
lib/
services/
db/
types/
prisma/
public/
```

### 4.1 各目录职责

- `app/`
  - 页面路由
  - 服务端组件
  - Route Handlers
- `components/`
  - 可复用 UI 组件
- `lib/`
  - 工具函数、常量、配置
- `services/`
  - 核心业务逻辑
- `db/`
  - 数据访问封装
- `types/`
  - TypeScript 类型定义
- `prisma/`
  - 数据库 schema 和迁移

## 5. 推荐架构方式

### 5.1 不是“前后端分离”，而是“分层”

建议按下面的方式组织代码：

- 页面层：负责展示
- 服务层：负责业务规则
- 数据层：负责数据库读写

这样做的好处是：

- 代码不会全塞在页面里
- 后续拆后端时更容易迁移
- 现在开发速度也不会慢

### 5.2 服务端优先

这个产品不需要复杂前端状态管理。

建议尽量用：

- Server Components
- Server Actions
- Route Handlers

这样可以减少不必要的 API 往返。

## 6. 数据库建议

推荐使用 PostgreSQL。

原因：

- 结构清晰，适合关系型数据
- 事务和约束能力好
- 未来扩展用户、团体、打卡记录都方便

### 6.1 核心表

- `users`
- `groups`
- `group_members`
- `tasks`
- `checkins`
- `daily_group_status`（可选）

### 6.2 设计原则

- 任务是系统预设，不允许用户改配置
- 打卡记录只存事实，不存复杂统计结果
- 团体状态可以按日计算，也可以后续做缓存表

## 7. 部署建议

你有云服务器的话，最稳的方式是：

### 方案 A：Docker 部署

适合长期维护。

组件：

- Web 应用容器
- PostgreSQL 容器
- Nginx 反向代理

优点：

- 环境一致
- 迁移简单
- 后续扩容容易

### 方案 B：直接 Node 部署

适合极简启动。

优点：

- 上线快
- 配置少

缺点：

- 环境可控性不如 Docker
- 后续迁移成本更高

如果你准备长期做这个产品，我更推荐 **Docker**。

## 8. 未来什么时候拆前后端

只有在下面情况出现时，才建议拆分：

- 你要接 App、小程序、H5、多端
- 后端业务明显变复杂
- 团队里前后端已经分工明确
- 需要独立的 API 网关或服务治理

到那时可以把后端迁到：

- NestJS
- Fastify
- 独立 API 服务

但这不是现在要做的事。

## 9. MVP 开发顺序

建议按下面顺序推进：

### 第一阶段：基础闭环

- 项目初始化
- 登录/匿名昵称
- 团体加入
- 固定事项展示
- 打卡记录写入
- 今日团体状态展示

### 第二阶段：体验完善

- 首页和团体页打磨
- 每日结算
- 通知
- 空状态和失败状态

### 第三阶段：运维增强

- Docker 化
- 服务器部署
- 日志
- 备份

## 10. 推荐的最终选择

如果你现在要直接开工，我建议最终采用：

```text
Next.js + TypeScript + PostgreSQL + Prisma + Tailwind CSS + Docker
```

这是一个很适合你当前产品阶段的组合：

- 足够快
- 足够稳
- 足够简单
- 未来也能扩展

## 11. 一句话总结

**现在先不要做前后端完全分离，先用 Next.js 做单体全栈，把产品闭环跑通。**
